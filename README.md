# investment-quote-coda

**在投资、决策、认知类对话的结尾，偶尔附一句值得玩味的经典金句。**

一个给 AI Agent（WorkBuddy / Claude Code / Codex 等支持 Skill 的宿主）用的技能：聊到投资、理财、复盘、认知偏差时，在回复末尾偶尔补一行书籍金句，作为一次精神提示或一次放松——不承担信息功能，只承担「节奏」与「心气」功能。

```
> 「如果失败的代价过于沉重、难以承受，那么这件事成功的概率有多高根本无关紧要。」——《随机漫步的傻瓜》 纳西姆·尼古拉斯·塔勒布
```

---

## 它解决什么问题

投资类对话里，人真正需要的往往不是再多一条数据，而是**在紧张处被提醒一次常识**。这个技能把「提醒」做成了一件克制的事：

- 约 **每 5 轮**投资类对话才出现一次，单次会话最多 3 次
- 用户处于亏损压力、焦虑或紧急决策状态时**不出现**
- 只占一行，**不加引导语、不解释金句**，让读者自己完成这一步

## 安装

支持 Skill 协议的宿主体系，将本目录放到技能目录即可：

```bash
# WorkBuddy / 兼容 ~/.workbuddy/skills 的宿主
git clone https://github.com/CT42X/investment-quote-coda.git \
  ~/.workbuddy/skills/investment-quote-coda
```

## 使用

```bash
# 随机抽一句（全池加权随机，自动避开最近用过的 80 条）
python3 scripts/quote_pick.py

# 按主题限定
python3 scripts/quote_pick.py --tag risk

# 按书限定
python3 scripts/quote_pick.py --book 金钱心理学

# 一次抽 3 条
python3 scripts/quote_pick.py --n 3

# 查看池子规模与累计引用次数
python3 scripts/quote_pick.py --stats

# 查看各主题可用条数
python3 scripts/quote_pick.py --tags
```

可用主题标签：`risk` `allocation` `cost` `value` `mind` `cycle` `fundamental` `wealth` `habit` `life` `health` `startup`

输出已经是可直接粘贴的引用行，无需再加工。

## 抽句逻辑

不是均匀随机，而是**加权随机**：

```
权重 = max(金句感评分 − 5, 0.5) ^ 1.5 × (1 + log₁₀(划线人数 + 10))
```

即金句感越强、划线人数越多的句子越容易被抽中，低分句仍在池中但概率更低。使用记录落在 `state.json`，自动避开最近 80 条，短期不重复。

## 筛选口径

原始 74,776 条划线，最终留下 519 条：

1. **清洗** — 去公式、去希腊字母、去章节引用、去元叙述、去说教句、去残句形态
2. **全量近似去重** — 长度邻域分桶比对，避免 O(n²)
3. **形态排除** — 承接残句开头（而／但／它／这／也就是说…）、含省略号（截断）、以引号开头（对话片段），一步剔除 4,087 条
4. **金句感评分** — 主题词 + 领域词 + 金句感词 + 对举结构 + 长度 + 引用量对数权重；并对**纯陈述句**（指代具体对象 + 罗列经营财务指标）扣 2.5 分、**定义句**扣 1.5 分
5. **按类目门槛入围** — 投资类 6.5；成长／创业 6.2；时间／健康 6.0（新类目语汇密度低，单独降门槛）
6. **人工黑名单**（539 条）剔除 + **每本配额** + **人工白名单**（40 条手挑金句，绕过阈值与配额）

## 重建

```bash
python3 build/build_pool.py
```

- 输入 `data/quotes_final.json`（原始划线，**未随仓库分发**，可用 WorkBuddy 的 `weread-highlights` 技能重新抓取），输出 `data/quote_pool.json`
- **两段式**：解析／清洗／评分／全量去重（最贵，约 4.5 分钟）落 `build/stage1.json` 缓存；调参时用 `REUSE_STAGE1=1 python3 build/build_pool.py` 秒级重跑
- ⚠️ 改了 `data/quotes_final.json` 必须先删 `build/stage1.json` 再重建
- 维护要点见 `SKILL.md` 的「重建」一节
